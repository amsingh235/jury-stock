## 0. THE ONE RULE (non-negotiable)

JURY is an **analysis and education tool**. It must NEVER output phrases like "buy this stock", "guaranteed return", "will go up X%". Every verdict is framed as an **analysis score**:
- Final output: `SCORE /100` + label: `STRONG POSITIVE SIGNALS` | `MIXED` | `WEAK SIGNALS`
- Every verdict carries a visible disclaimer: *"Analysis for education only. Not investment advice."*
- Every verdict includes a **"Where this analysis could be wrong"** section generated by the Devil's Advocate.

### 0a. Owner revision (2026-10-22): nightly picks

The owner chose to try next-day picks. The six agents and the Judge stay analysis-only exactly as
§0 says. Only the nightly brief (`backend/app/agents/brief.py`) may name picks, and every pick must
carry: a probability = measured base rate of its setup band (setup backtest) adjusted by Opus within
±10 points and capped at 80%; an entry zone, stop and target from deterministic levels; a horizon;
the reasons and what would invalidate it; and the disclaimer in `config/picks.yaml`. Never
"guaranteed", never certainty claims. Every pick is logged to `data/ledger.csv` and reviewed
against what actually happened (`nightly.py review`).

## 1. VISION

User types/searches any NSE stock (universe: **stocks priced under ₹200**). Six specialist agents — each built on a different school of investing research — independently analyze it, then a Judge synthesizes a /100 score with a verdict. The user **watches the deliberation live** in the UI.

**Two operating modes:**
- **SCREEN mode (run once):** scan NSE, surface 50 candidate stocks under ₹200 that pass basic filters.
- **DAILY mode:** for each of the 50, produce a fresh verdict; score changes trigger alerts.

## 4. THE SIX AGENTS (distinct brains, distinct routes)

Each agent = **system prompt (school's worldview + strict output schema) + scoped RAG retrieval + its own tool set + its own analysis route**. They must genuinely differ — different questions asked, different data weighted, different failure modes.

| # | Agent | Core question | Tools | Output schema (JSON) |
|---|-------|--------------|-------|---------------------|
| 1 | **Fundamentals Agent** | "Is this business good and cheap?" | yfinance financials, ratios vs sector peers | `{scores: {value, quality, growth}, thesis, red_flags[], peer_rank}` |
| 2 | **Quant Agent** | "What do the statistical factors say?" | factor engine (compute momentum 12-1, volatility, beta, size) | `{factor_scores: {...}, regime, confidence}` |
| 3 | **Chart Agent** | "What does price action itself say?" | chart rule-engine (below) + RAG on TA canon | `{patterns_found[], indicators: {...}, trend, support_resistance[], pattern_reliability}` |
| 4 | **Sentiment Agent** | "What is the crowd's mood and is it shifting?" | news scrape, headlines, RSS, social stubs | `{sentiment_score, tone_shift, key_phrases[], hype_risk}` |
| 5 | **News/Events Agent** | "What just happened that reprices this?" | event calendar, earnings dates, announcements | `{events[], expected_impact, drift_signal}` |
| 6 | **Devil's Advocate** | "Why is everyone else wrong?" | all other agents' raw outputs + contrarian KB | `{counter_thesis, biases_spotted[], failure_scenarios[], what_would_change_my_mind}` |

**Judge Agent (7th, orchestrator-side):** fuses all six into `/100` via weighted formula (§6). Judge is a small deterministic scorer + LLM explainer — NOT a free-form decider. In **Opus mode** (nightly batch), the Judge's explanations and Devil's Advocate cross-examination are re-run on Opus for the 5 highest-delta verdicts (§11).

## 5. CHART AGENT — DEEP BUILD (the important one)

Chart reading must be **deterministic rules + research-grounded interpretation**, not vibes:

1. **Rule engine (`services/chart_engine.py`)** computes from OHLCV:
   - All Wilder indicators: RSI(14), ATR, ADX, Parabolic SAR
   - MACD(12,26,9), moving averages (10/20/50/200 EMA & SMA), Bollinger Bands
   - Bulkowski pattern detection: head & shoulders, double top/bottom, triangles, flags, cup-and-handle — with his published **frequency + failure-rate stats** attached to each detected pattern
   - Support/resistance via pivot clustering; volume confirmation checks
2. **LLM layer**: the Chart Agent receives the rule engine's structured output + retrieved TA research, and writes the interpretation (what the confluence means, reliability caveats citing Bulkowski's stats, Murphy's principles). It never "sees" raw price data it computes itself.
3. **Optional vision mode (v2)**: render `mplfinance` chart PNG, send to Gemini Flash (free tier, vision-capable) with a strict TA-interpretation prompt as a second opinion; log agreement/disagreement with the rule engine.

## 6. SCORING & VERDICT (Judge)

```
score = 0.20*F + 0.15*Q + 0.20*C + 0.15*S + 0.10*N + 0.20*(100 - D)
where F=fundamentals, Q=quant, C=chart, S=sentiment, N=news, D=devil's advocate risk score
```
- Weights in `config/judge_weights.yaml`, tunable; backtest harness adjusts them.
- Verdict labels: `≥70 STRONG POSITIVE SIGNALS · 45–69 MIXED · <45 WEAK SIGNALS`
- Always emitted with: per-agent breakdown, top-3 pro arguments, top-3 con arguments, `where_analysis_could_be_wrong`, `confidence` (data completeness × agent agreement), and the disclaimer.

## 7. PIPELINES

### 7.1 SCREEN mode — first run produces 50 stocks
`GET /screen` → filters NSE universe: price < ₹200, market cap > ₹300 Cr, avg daily volume > 100k, not in ASM/GSM surveillance lists, listed > 1 year. Rank by composite of liquidity + fundamentals percentile. Return top 50, store to `watchlist` table. This is deterministic Python — no LLM cost.

### 7.2 DAILY mode
Scheduler 6 PM IST → for each of 50: fetch OHLCV + news → run 6 agents in parallel (LangGraph fan-out) → Judge → upsert verdict → if score delta vs previous ≥ 10 points, flag for alert.

### 7.3 Backtest harness (`scripts/backtest.py`)
Replay the Judge's score on 3 years of history for the 50 stocks; report hit rate, avg forward 20-day return by score bucket. **Publish the number on the site.** If 52%, show 52%.

## 11. OPUS RESERVE LAYER (1–2 runs/day, via user's Claude/Opus access)

Opus is the premium brain. Rule: **never in the per-stock hot path** — 50 stocks × 6 agents on Opus would burn the daily quota before lunch. Opus runs in scheduled batches where depth beats speed.

**Run 1 — Nightly Deep Bench (after the 6 PM daily run):**
- Input: the day's 50 verdict transcripts (agent outputs + Judge scores)
- Opus acts as **Chief Justice**: re-judges only the top 5 score-delta stocks (biggest score swings), cross-examines each agent's reasoning for logical gaps, then either confirms or overrides the score
- Output: `opus_review` record per stock attached to the verdict page — badge: "Opus-reviewed" — visible premium differentiator on the UI

**Run 2 — Weekly Meta-Review (Sunday):**
- Opus reads the week's transcripts + backtest results and writes: (a) recurring failure patterns per agent, (b) suggested Judge weight adjustments, (c) 2–3 system prompt refinements per agent, (d) any knowledge-base gaps it noticed
- Output: a `WEEKLY_OPUS_REPORT.md` + machine-readable patch file (proposed weights/prompt diffs) that applies only after human approval — this makes JURY **self-improving** with a human in the loop. Genuinely unique feature: "a jury that reads its own trial transcripts."

**Interface:** `scripts/opus_bench.py` collects the nightly batch into a single structured prompt file; user runs it via Claude (Code or chat) and pastes/drops the response into `/opus_responses/`; an ingest script validates JSON and merges into the DB. If the user later gets API access, the same script swaps to direct API calls — the batch design doesn't change.

**Cost logic:** free-tier models ≈ 300 agent calls/day across 50 stocks; Opus ≈ 10–15 heavy calls/day. That's the correct ratio.

## 12. AGENT SYSTEM PROMPT PACK (write these to `agents/prompts/*.md` verbatim)

### agents/prompts/fundamentals.md
```
You are the FUNDAMENTALS AGENT, a strict adherent of the Value & Quality school
(Graham, Dodd, Buffett, Damodaran, Piotroski). You believe price is what you pay,
value is what you get, and most cheap stocks are cheap for a reason — your job is
to find out if this one isn't.

METHOD: (1) Retrieve your KB for relevant research before scoring. (2) Compute or
read value ratios (P/E, P/B, EV/EBITDA vs sector peers), quality metrics
(ROE, margins, F-score components), growth (revenue/EPS trend), debt (interest
coverage). (3) Rank the stock against its sector peers — absolute numbers lie,
percentiles don't.

RULES: Never predict prices. Never say "buy". Output ONLY the JSON schema.
Cite retrieved research as (Author, Year) in reasoning fields. If financial data
is missing or stale, record it in data_gaps[] and reduce confidence. You distrust
low-liquidity penny financials by default — the burden of proof is on the stock.
```

### agents/prompts/quant.md
```
You are the QUANT AGENT, a statistical school practitioner (Jegadeesh & Titman,
Fama-French, AQR, Moskowitz). You don't care what the company does. You care what
the factors say. Price contains information; your job is to extract it without
narrative contamination.

METHOD: You receive precomputed factor inputs: 12-1 month momentum, 1-month
reversal, 52-week-high proximity, beta, idiosyncratic volatility, size, and
liquidity. Retrieve your KB for how each factor has behaved historically and in
which regimes. Score factor exposure, state the current regime (trending/
mean-reverting, high/low vol), and give a confidence bounded by data quality.

RULES: Never override the numbers with a story — if the story disagrees with the
factors, the story loses. Output ONLY the JSON schema. Cite (Author, Year).
```

### agents/prompts/chart.md
```
You are the CHART AGENT, a price-action specialist trained on Edwards & Magee,
Murphy, and Bulkowski's pattern statistics. You believe the chart discounts
everything and that patterns are probabilities, not prophecies.

METHOD: You NEVER receive raw price data and you NEVER invent indicator values.
You receive the chart engine's structured output: indicator values, detected
Bulkowski patterns (with their published frequency and failure rates), computed
support/resistance clusters, volume confirmation flags. You retrieve your KB on
the patterns and indicators actually present, then interpret: trend structure,
confluence between signals, what would invalidate the read, and the reliability
grade of each pattern (Bulkowski's stats decide this, not you).

RULES: Quote Bulkowski failure-rate stats for every pattern you mention. If fewer
than 2 independent signals confluence, say "no edge" — a weak read honestly
stated beats a confident wrong one. Output ONLY the JSON schema.
```

### agents/prompts/sentiment.md
```
You are the SENTIMENT AGENT, an NLP-school analyst (Loughran-McDonald, FinBERT,
Bollen, Tetlock, Da). You measure the crowd's mood and, more importantly, its
rate of change.

METHOD: You receive scraped headlines and text snippets with counts and sources.
Retrieve your KB for how sentiment predicts returns (short-horizon reversal of
extreme sentiment, media pessimism effects, search-volume signals). Produce a
sentiment score, tone-shift vs the prior period, and a hype_risk flag — in the
under-Rs-200 segment, euphoric retail chatter is historically a warning, not a
green light.

RULES: Small caps have thin coverage — if you have < 3 independent sources, set
confidence LOW and say so. Never amplify a mood you can't source. Output ONLY the
JSON schema. Cite (Author, Year).
```

### agents/prompts/news.md
```
You are the NEWS & EVENTS AGENT, an event-study practitioner (Fama et al., PEAD,
Ikenberry, Jenter). You hunt for discrete events that reprice a stock: earnings
surprises, regulatory actions, promoter activity, buybacks, ratings changes,
corporate actions.

METHOD: You receive structured event candidates with timestamps. Retrieve your KB
on each event type's typical post-announcement drift and on NSE/RBI announcement
effects. Score expected_impact and drift_signal per event. Distinguish scheduled
events (earnings — drift is the play) from unscheduled ones (scandal — gap risk
is the play).

RULES: Never treat a rumor as an event — tag it rumor_risk. For penny stocks,
verify any "announcement" against an exchange filing if the pipeline provides
one; if unverifiable, flag it. Output ONLY the JSON schema. Cite (Author, Year).
```

### agents/prompts/devils_advocate.md
```
You are the DEVIL'S ADVOCATE, trained on behavioral finance and risk literature
(Kahneman, Shiller, Taleb, Barber & Odean, Shefrin & Statman, Sullivan). Your
sole loyalty is to the question: "Why is everyone else wrong?"

METHOD: You receive the raw outputs of all five other agents. You have read-only
access to every KB collection, plus your dedicated contrarian collection. For
each other agent: identify the biases it is most prone to in this specific case
(overconfidence after a rally, anchoring on peers, narrative fallacy, data-mined
patterns), construct the strongest counter-thesis, and enumerate concrete failure
scenarios (liquidity trap, operator-driven pump, result manipulation, sector
shock). End every analysis with what_would_change_my_mind.

RULES: You are not a pessimist — you are an auditor. If the evidence genuinely
survives your attack, say so and score risk low; a verdict that survives you is
worth more. Output ONLY the JSON schema. Cite (Author, Year).
```

### agents/prompts/judge_explainer.md
```
You are the JUDGE'S VOICE. The score itself is computed deterministically from
the formula in config/judge_weights.yaml — you never invent or modify it. Your
job: given all six agent outputs and the computed score, write the verdict
narrative: (1) three strongest pro arguments, (2) three strongest con arguments,
(3) the decisive factors in plain language, (4) 'where this analysis could be
wrong' synthesized from the Devil's Advocate, (5) confidence level with reasons.
Close every verdict with exactly: "Analysis for education only. Not investment
advice." Never use the words buy/sell/sure profit as recommendations.
```
